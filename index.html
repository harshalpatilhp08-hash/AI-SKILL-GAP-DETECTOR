Design Thinking Methodology

How We Designed This Prototype

Developed for our academic Design Thinking submission, following the 5-stage human-centered innovation framework.

Stage 1: Empathize — Understanding Student Placement Frustrations

RD
Rhea Deshmukh
3rd Year B.Tech CSE Undergrad
"Facing acute placement anxiety due to unknown industry expectations."

Core Goals

  • Secure a tier-1 software developer or web engineering campus placement.
  • Clearly know what campus recruiters evaluate versus what the university syllabus teaches.
  • Follow a structured, phased roadmap instead of wandering through disorganized video tutorials.

Key Frustrations & Pain Points

  • Overwhelmed by contradictory advice on YouTube, LinkedIn, and developer forums.
  • Unsure whether basic classroom coding projects meet actual production criteria.
  • Wasting weeks studying outdated technologies that recruiters no longer evaluate.

Field Interview Insights (College Cohort)

"I know how to write a basic loop in Java, but when I see technical job listings demanding System Design and CI/CD pipelines, I have no idea how far away I actually am."
— Siddharth, 6th Semester CSE
"College teaches us DBMS theory with normalization formulas, but tech interviews ask live SQL window functions and database indexing that we never practiced."
— Ananya, Final Year IT
"Whenever I want to prepare, I start 5 different video courses, get overwhelmed by 80-hour playlists, and quit after two weeks because there's no milestone tracking."
— Karan, 5th Semester ECE

Stage 2: Define — The Problem Statement

"Undergraduate engineering students lack an objective, automated mechanism to diagnose their concrete skill deficiencies against specific industry job roles, causing aimless preparation, high placement anxiety, and preventable interview rejections."
1. Skill Blindspots

Students equate superficial syntax familiarity with interview readiness, unaware of enterprise depth requirements.

2. Curriculum Lag

College syllabi lag industry hiring trends by 2-3 years, neglecting modern devops, containerization, and API architecture.

3. Decision Paralysis

Unfiltered course catalogs lead to tutorial abandonment without disciplined, phased milestone accountability.

Stage 3: Ideate — How Might We (HMW) Questions

HMW #1: How Might We objectively quantify a student's real skills from unstructured resumes?
Solution: A multi-tiered local NLP engine that normalizes skill aliases, cross-examines project mentions, and factors certification credentials into a deterministic 1-5 proficiency scale.
HMW #2: How Might We visualize gaps so students feel empowered rather than defeated?
Solution: A dual diagnostic dashboard pairing an overall Skill Gap Score donut chart with a domain-categorized radar chart that highlights existing strengths alongside high-priority areas for improvement.
HMW #3: How Might We convert gap diagnosis into daily prep momentum?
Solution: Automated chronological 2-week sprint generation prioritized by highest industry weight, complete with verified free resources and persistent localStorage progress checkmarks.

Stage 4: Prototype — System Architecture & Implementation

Core Technical Features

  • Zero build step, 100% client-side vanilla JavaScript architecture.
  • Deterministic weighted gap algorithm with 60+ industry competencies.
  • Chart.js integration for dynamic Donut & Multi-Axis Radar graphics.
  • Responsive glassmorphic UI adhering to dark navy-and-cyan aesthetic.
  • Print stylesheet converting report into clean academic placement PDF.

Extensibility Hook

Includes a clearly marked analyzeWithLLM() asynchronous function in app.js allowing drop-in connection to Gemini, Claude, or OpenAI APIs without modifying frontend presentation.
